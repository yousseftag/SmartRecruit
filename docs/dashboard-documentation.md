# Dashboard Feature Walkthrough & Documentation

## 1. Functional Specifications & Business Logic

The SmartRecruit Dashboard is the main landing page of the application, designed to give recruiters immediate visibility into their pipeline and tasks. The content is broken down into four highly specific modules:

### 1.1. Key Performance Indicators (KPIs)
The top section features 5 core metric cards calculated from the entire database:
*   **Active Offers (`activeOffers`)**: The total count of job offers that are currently in the `PUBLISHED` state. It gives an immediate sense of the recruiter's active workload.
*   **New Applications (`newApplications`)**: The total count of candidate applications currently sitting in the `NEW` state across all offers. These are profiles awaiting human review.
*   **AI Performance (`aiValidationRate` & `cvExtractionRate`)**: 
    *   **CV Extraction Rate**: The percentage of `NEW` applications where the AI successfully parsed the CV into structured data (JSON).
    *   **Validation Rate**: The percentage of `NEW` applications where the candidate's score exceeded the minimum threshold defined for the job offer (represented by `passed_min_score = true`).
*   **Applications in Process (`activeCandidates`)**: The total count of applications that are actively moving through the pipeline (e.g., `SHORTLISTED`, `INTERVIEWING`, `OFFER_SENT`). This excludes `NEW`, `HIRED`, and `REJECTED` applications.
*   **Hiring Funnel (`hiringSuccessRate`)**: Displays the raw number of `HIRED` vs `REJECTED` candidates. It calculates the success rate as: `(HIRED) / (HIRED + REJECTED) * 100`.

### 1.2. Applications Chart
*   A bar chart displaying the volume of applications received over the **last 7 days**. 
*   It helps recruiters identify trends (e.g., spikes in applications after publishing an offer on a specific day).

### 1.3. Recent Activity (Timeline)
*   A chronological feed limited to the **10 most recent actions** across the entire platform.
*   It tracks three specific event types:
    1.  `CREATE_OFFER`: When a recruiter publishes a new offer.
    2.  `UPDATE_OFFER`: When a recruiter modifies an existing offer.
    3.  `STATUS_CHANGE`: When a candidate's application is moved from one step to another (e.g., from `SHORTLISTED` to `INTERVIEWING`).
*   Each event clearly identifies the **User** who performed the action, the **Target** (Offer Title or Candidate Name), and the exact **Timestamp**.

### 1.4. Priority Offers
*   A list of the top 5 most urgent job offers.
*   **Sorting Logic**: Offers are sorted in descending order based on the number of `NEW` applications they have. An offer with 15 unread applications will appear above an offer with 2.
*   It also displays a badge indicating how many of those new profiles passed the AI minimum score, helping recruiters know if there are high-quality candidates waiting.

## 2. Optimisation & Technical Details

### 2.1. Backend: Native Queries & Optimization
The backend (Spring Boot) has been drastically optimized to avoid excessive memory loading (solving N+1 selects and heavy Java loops).
- **Native SQL Queries**: Complex statistics (KPIs) and the activity feed are generated by highly optimized native SQL queries.
- **UNION ALL**: The "Recent Activity" timeline merges two distinct business concepts (`WorkflowStatusHistory` for candidates and update dates for `Offer`) using a SQL `UNION ALL`. This allows us to retrieve a combined and chronologically sorted history directly from PostgreSQL.
- **Pure DTOs**: The Backend only returns structured data objects (JSON). No visual formatting (like HTML tags) is produced by the server.

### 2.2. Frontend: Lazy TTL Caching
The frontend (Angular) has been modernized and optimized to reduce network load:
- **Lazy TTL Caching with RxJS**: Instead of calling the API every time the user navigates to the Dashboard, a 5-minute "lazy" cache (Lazy TTL) was implemented using `shareReplay(1)` and timestamps (`Date.now()`). The API is only queried if 5 minutes have passed since the Dashboard was last visited.
- **Tailwind Design**: A clean integration using Lucide icons (`<svg lucideXxx>`) and adhering to a semantic color palette (Blue for candidates, Green for users, Amber for offers/statuses).

## 3. ⚠️ CRITICAL WARNING FOR OTHER MODULES

For the Dashboard to calculate its metrics correctly, the database schema was updated with new fields. **These fields MUST absolutely be populated by the other features of the application (Offer Creation, CV Analysis, etc.).**

> [!CAUTION]
> **If these fields remain `null`, the Dashboard may display calculation errors. **

### Field: `application.passed_min_score` (Boolean)
- **Where?** In the `Application` entity.
- **Role:** Used to calculate the "AI Performance" KPI.
- **Action Required:** The AI module (which parses the CV and compares it to the offer) **must** set this field to `true` or `false` depending on whether the candidate's score exceeds the threshold required by the offer. Never leave it as `null` once the analysis is complete.

### Field: `offer.updated_by` (UUID)
- **Where?** In the `Offer` entity.
- **Role:** Used to display who created or modified an offer in the Recent Activity Timeline.
- **Action Required:** The controllers and services responsible for creating (`POST /offers`) and modifying (`PUT /offers`) an offer **must** extract the connected user's ID and populate this field in the database. If this field is omitted, the Timeline will display `"System"` by default.

### Auditing: `WorkflowStatusHistory`
- **Action Required:** Every time an application changes status, a new row **must** be inserted into the `workflow_status_history` table by the backend. This table feeds the recent activity stream.

## 4. Tests and Validation
- **Backend Tests**: `SpringBootTest` classes cover nominal scenarios and Edge Cases (Division by zero if no applications exist, empty database handling, native query mappings with the `COALESCE` SQL clause).
- **Dummy Data**: A Flyway migration file (`V4__dashboard_dummy_data.sql`) was created to simulate a coherent history and allow immediate visual testing on the UI.
